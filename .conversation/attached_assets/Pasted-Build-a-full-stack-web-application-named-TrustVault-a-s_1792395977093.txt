Build a full-stack web application named **TrustVault**, a secure document-sharing platform for the Thesnovasys hiring challenge.

I am a beginner, so create a well-organized, maintainable project that I can understand and explain during an interview.

**Technology stack**
- Frontend: React with TypeScript.
- Backend: Python with FastAPI.
- Database: PostgreSQL.
- Automated tests: pytest.
- Use environment variables for secrets and configuration.

**Core requirements**
1. Authentication with administrator, document owner, and viewer roles.
2. Document upload, categorization, search, metadata editing and deletion.
3. Per-document read and edit permissions granted to named users.
4. Owners can grant and revoke permissions.
5. Documents must be stored privately, never in a public static directory.
6. Every document read, download, modification, deletion, permission change, and denied access attempt must be audited.
7. Search by document name, owner, category and date.
8. Validate uploaded file size, file type and content. Use safe storage names rather than trusting uploaded filenames.
9. Provide an administrator dashboard for document activity and permission changes.
10. Include automated authorization tests proving that one user cannot access another user's documents.

**Security rules**
- Enforce authorization on the server for every protected API request.
- Never rely on hidden frontend buttons or client-supplied role values for security.
- Deny access by default.
- Check permissions against the requested document on every read, download, edit, delete and sharing operation.
- Revocation must prevent subsequent requests from using previously granted access.
- Do not expose public or reusable download URLs that bypass authorization.
- Passwords must be securely hashed.
- Protect audit events from ordinary application-level modification and document the limitations of the chosen audit design.
- Do not automatically grant document access based on AI recommendations.
- Never place real passwords, API keys or secrets in source code.

**Development instructions**
- Start with the project structure, database schema, authentication, authorization and security tests.
- Add the user interface after the security foundation.
- Use migrations and provide seed data for three test roles.
- Include `README.md`, `THREATS.md`, `PROMPTS.md` and API documentation.
- Keep the code readable, with explanations suitable for a beginner.
- Add tests for unauthorized access, guessed document IDs, privilege escalation, revoked access, unsafe uploads and audit integrity.
- Do not claim a feature is secure or tested unless it has actually been implemented and verified.
- Do not fabricate test results, audit guarantees, commit history or AI development records.

First inspect the available Replit environment and create the initial project structure. Explain the files created and the next steps. Do not attempt to implement everything in one unverified step.
